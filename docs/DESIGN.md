# Jadeslip core design

The goal is a Rust and Tauri desktop app where a 6,000-chapter EPUB shows readable text instantly, with one Read and Edit switch on every book.

## Edit model

The chapter's source XHTML is the truth. An edit splices token-trimmed changes into the blocks that changed, never a tree diff of the whole chapter. In the largest test novel, 6,110 of 6,193 items are one `div` of text and `<br>`, and a typo there must change only the typo. A larger write than needed is recoverable, while a save blocked by a false mismatch is not.

### Rules of the edit path

1. **Verify before every write.** After `splice`, re-scan the result and compare its tokens and `VisibleText` with what was intended. On a mismatch, widen to the whole block and retry once. On a second mismatch, write nothing, keep the user's DOM and report it. `commit` also re-opens the temp.
2. **Return path uses `XMLSerializer`, not `outerHTML`.** 401 of 401 chapters round-tripped through XML mount and `XMLSerializer` in WebKitGTK. Blocks are serialised individually. `BlockChange.html` becomes `BlockChange.xml`. The tolerant scanner still parses it. `canon_html` keeps its sanitiser pass.
3. **Invertible URL map instead of `data-ss-orig-*`.** `UrlMap::to_scheme` and `to_source_href` are pure, so the DOM carries no second attribute that could be forged. Unchanged attributes keep their source bytes through the token trim. A test asserts no saved entry contains `jadeslip-book:`.
4. **WebKit edit artefacts are handled in `canon_html`, from a closed, tested list.**
   - U+00A0 compares equal to a space in canon text, and any U+00A0 in changed text is written as a space. Source NBSP outside the changed middle keeps its bytes.
   - A block's trailing `<br/>` left by WebKit in an empty block is dropped.
   - A duplicate `id` from a split stays on the first element.
   - `style` attributes matching WebKit's inserted styling are not treated specially until a real session shows they occur.
5. **`revert_list` compares central-directory CRCs against the backup,** so it reads no entries.
6. **A replacement crossing a block boundary is refused and counted.** It appears in the preview as skipped.
7. **The attack test moves to before any feature.** It runs on the XML mount path.
8. **Whole-chapter fallback is no longer the only recovery.** The verify retry provides a bounded path.

### Also

- Token trim over a general tree diff, and no `Tree<O>` markers.
- `BlockEdits` naming dirty blocks, driven by a `MutationObserver`. An empty dirty set sends nothing. Dirtiness is a hint, and the canon comparison decides.
- Raw whitespace kept in the display, so a book's `white-space: pre-wrap` works.
- Regex in a separate `jadeslip-worker` crate, so core cannot call fancy-regex in process.
- Deleted chapters keep their latest bytes under `deleted/`.

### Not done

- A tree type per origin, Myers diff and `verify` projection. These stay the fallback if the scanner path shows repeated friction.
- `data-*` ids per node. Marking every node adds noise to book markup, and WebKit clones them on split.
- Treating U+00A0 as collapsible in the text model. Search should see what the book has, so only the canon comparison folds it.

## Behaviour decisions

- A typed non-breaking space is written as a plain space in version one, including in books the user writes.
- Esc in Edit saves without asking and returns to Read. The backup and Revert cover mistakes. A close or chapter change with unsaved edits still asks.
- A malformed chapter stays editable. Its first real save repairs it, with a warning.
- The original backup a book's Revert uses is never removed automatically. Preferences > Storage has Delete original backup per book, which asks first, names the size, and says that Revert and restoring chapters deleted since then end with it.
- Two files with the same fingerprint are one book. The shelf holds one copy of it, and both files share its place, notes and backups.
- Search and fix everywhere skip the nav document.
- The pane has a range strip under the mode row, "◀ Earlier | Ch. 12 | Later ▶". The middle names the chapter the range counts from, and that chapter is always included. Earlier and Later are on by default and switch off with a click. Earlier alone keeps later chapters out of the results, so a reader can look something up without spoilers. With both off only that chapter shows. With no place at all the strip is disabled and says "Open a chapter first".
- A search always covers the whole book and the boxes only filter its rows, so switching a side is instant and starts nothing. The whole book runs again when the results cannot answer: the book changed, or the run was stopped before it finished. A run that stopped at the 100,000 cap runs the narrower range on its own instead, since the whole book would stop at the same cap. Replace previews still run on the range itself, because Apply saves exactly what the preview found.
- The chapter the strip counts from is set when the first side switches off, to the chapter being read, and then does not follow the reader. Switching sides, jumping to a result, typing, Rerun and the refresh after an apply keep it. When the reader is elsewhere, the middle chip lights up and a click moves the range to the chapter being read.
- The status counts what the search covered, "6,000 of 6,000 chapters searched", and leaves the range to the strip above it. The match counts, the search field and the replace button follow the range, "Search ch. 3001 only" and "Apply to ch. 3001 and after".
- Hiding and showing the side panel, with Ctrl+T or the tab buttons, keeps the rows, the strip and the chapter it counts from.
- Fix everywhere and its Review each always cover the whole book, whatever the pane's switch says. Saved and recent searches carry no range.
- Results stop at 100,000, not the 1,000 in the reference copy, so a common word stays browsable. It is one constant, `MAX_HITS` in `app/src/search.rs` and `MAX_RESULTS` in `app/ui/search-model.js`.
- The pane has Plain and Regex and one Match case toggle beside them, as Calibre does. Match case is off by default, so plain and regex search both ignore case, and one setting covers both modes. Before this, plain ignored case and regex did not. A pattern can still override it with `(?i)` or `(?-i)`. Plain search is not whole-word. Whole word exists in the library for fix everywhere.
- Match case is saved in prefs.json as `matchCase` and comes back after a relaunch. A file from before it, or a value that is not true or false, reads as off.
- Replace across book uses the same Match case setting as the search, and its preview lists exactly the matches it will change. The replacement is inserted as typed. It does not copy the case of each match.
- Fix everywhere keeps its own case rule and ignores Match case. It changes the typed word, its capitalised form and its all-capitals form, and nothing else.
- Turning Match case on or off reruns the current query at once. While a fix everywhere preview is open, it does not, because that preview ignores the setting.
- The top bar of the pane counts chapters, "2,519 of 2,519 chapters searched". The match count is the bold line at the bottom, "2,911 matches.", and reads "Match 4 of 2,911." while stepping. The two numbers never share a line, so a chapter count cannot be read as a match count.
- Jadeslip searches the text a reader sees. Calibre also searches the HTML source and the chapter titles, so on the same book and pattern Calibre can report a few more matches. On the 2,519-chapter book that prompted this change, Calibre found 2,986 and Jadeslip finds 2,976 with case ignored.
- A regex search gets 250 ms per chapter plus 100 ns per byte, and 5 s for the book. Past that it reports too slow and counts what it did not finish.
- Esc in focus mode runs from the innermost layer out: apply overlay, unsaved dialog, palette, text controls, the saved and recent search list, a field, then Edit, which saves and returns to Read while focus stays on, then the open search pane. Only Read in focus with the search pane closed leaves focus.
- F11 toggles full screen in Read and in Edit, as it does in browsers and Calibre. Focus moved to Shift+F11 in both modes, and F still enters focus in Read.
- Esc in Read leaves full screen and focus together. Esc in Edit keeps its save meaning, so F11 leaves full screen there. Full screen is window state and is not saved across launches.
- Full screen goes through an app command, `set_fullscreen`, like `close_window`, so the window capability list stays empty. If the compositor leaves full screen on its own, the app still thinks it is on until the next F11.
- Column width is the text column, not the sheet. The four margins sit outside it, so a margin change never changes the line length. Old saved widths keep their look: Narrow, Medium and Wide become 516, 636 and 816 px of text. The range is 400 to 1400 px.
- Line spacing, paragraph spacing, first-line indent and the reading font reach a chapter the way text size does, by inheritance and a zero-specificity paragraph default. A book that sets its own line height, paragraph margins, indent or font keeps them. The sampled web novels set none of these. The sampled technical books set most of them.
- First-line indent at zero reads "Book's own" and leaves the book's indent alone rather than forcing none. There is no "Book's own font" choice, because every face already yields to a font the book names.
- Margins are in px and do not grow with text size. Reset layout puts back width, margins, spacing, indent and font, not text size or theme.
- New installs read at 18 px, line spacing 1.60 and paragraph spacing 0.60 em, against the first defaults of 19 px, 1.72 and 1.05 em. At the top of chapter 1818 of the largest test novel in a 1256 by 750 window with the contents open, a screen holds 113 words instead of 88, and 127 with Compact. A saved prefs.json keeps its values, including the old defaults it wrote out, because the file cannot tell a chosen value from a written default.
- The Text tab has two spacing presets. Compact is 17 px, 1.50 and 0.40 em. Comfortable is the new default. A preset sets text size, line spacing and paragraph spacing and lights up while all three match. There is no Book preset, because the zero-specificity defaults already yield wherever a book sets its own spacing.
- Ctrl and the wheel, Ctrl +, Ctrl - and Ctrl 0 change the reading text size in Read, Edit and focus, one px a step, and keep the place. A readout shows the size for 0.9 s. Ctrl 0 goes back to 18 px. The page catches every Ctrl wheel event, so WebKit's page zoom never runs, and Tauri's zoom hotkeys stay off, so the chrome never scales.
- A book that cannot be opened at launch or from the shelf shows a card in place of the text: a plain sentence naming the path, Back to shelf, Find the file for a missing file, and Remove from shelf when the shelf knows the book. The toolbar, contents and footer are inert while it shows. Find the file relinks the shelf record when the picked file is the same book, judged by the same fingerprint and aliases the shelf keys on, and refuses a different book in a sentence that names both.
- Errors from the disk reach the page as plain sentences from `plain_io` in core, by error kind. No message carries "(os error N)".
- In Edit the sheet keeps its top padding at zero, as before, so the Top margin applies in Read only.
- The mouse edges leave focus but not full screen. Esc in Read and F11 leave full screen.
- A slider repaints on every step of a drag and writes prefs.json once, on release.
- The layout lives in custom properties on `.sheet`: `--measure`, `--margin-top`, `--margin-right`, `--margin-bottom`, `--margin-left`, `--line-height`, `--para-gap`, `--para-indent` and `--reading-font`. A paged layout reuses them.
- The top, left and bottom edges leave focus. The right edge belongs to the scrollbar, so it does not.
- Ctrl+F and the Search this book command open the search pane inside focus mode instead of leaving it. Only the search pane joins the text. The toolbar, contents, footer and notes stay hidden.
- The search pane takes its own 360 px beside the text and never covers it. When Auto's two pages no longer fit beside it, one page shows while it is open and two come back when it closes, on the same text both ways.
- The Exit focus button moves left of the open search pane so the pane's controls stay reachable.
- The mouse edges do not leave focus while the pointer is over the open search pane, so reaching for the search field at the top or the match count at the bottom keeps focus.
- In Read, Enter and F3 go to the next match, Shift+Enter and Shift+F3 to the previous one, wrapping at both ends. Enter steps only from the search field. F3 works from anywhere. With the pane open it leaves keyboard focus where it was, so arrow keys and Space still turn pages from the page. With the pane closed it opens the pane in the search field.
- The first Enter goes to the first match in result order, not the first match after the current page. A clicked result becomes the current match, so the next Enter continues from it.
- Enter pressed before the results of a new query arrive waits for its first match and then goes to it, rather than stepping through the previous query's results.
- The pane footer reads "Match N of M" once a match is current, with "so far" while the search runs. The current row is tinted in the list and kept in view.
- In Edit, Enter in the search field and F3 do nothing, so a key in the field never moves the caret's chapter or ends the edit. A clicked result still jumps there as before.
- A step to a match in the shown chapter moves the page without remounting the chapter. A step to another chapter goes the way a clicked result does.
- Esc runs from the innermost layer out with the search pane counted as a layer: with the pane open, Esc closes it, from the field or from the page, and focus and full screen stay. The next Esc leaves them as before.
- Saved and recent searches are app-wide, not per book. They live in `searches.json` in the data folder, written through a temp file and a rename like prefs.json. A saved search has a name, the text, Plain or Regex, and Match case. Recent searches keep the same three without a name. The file is read at the boundary: entries with empty text, text over 16 KB (the search limit), a blank or padded name, a name over 80 characters, a name another entry already has ignoring case, or a query another saved entry already has are dropped, and the lists stop at 200 saved and 50 recent. A file over 16 MB or from another version reads as empty. Writing refuses what reading would drop.
- A search joins Recent only when it is used, not as it is typed: Enter or F3 from it, a clicked result, Rerun, running it from the list or the palette, or closing the pane or the book while its finished results show. So typing `zeph` on the way to `zephyrquill` keeps only `zephyrquill`. A search whose pattern failed is never kept. Running one again moves it to the top. A recent search that is also saved shows only under Saved.
- Ctrl+F and the list button under the search field show Saved on top and Recent below. Typing filters both by name and text. Down picks from the top, Up picks the newest recent search, so Up then Enter reruns the last search. Picking a row does not change the field. Enter runs the picked row with its mode and Match case. Enter with no row picked closes the list and steps through matches as before, so the list never takes Enter from stepping. Esc with the list open closes only the list and keeps the field.
- Save checks a regex with the same worker that runs it. The save waits for the field's search to compile and refuses a pattern the worker rejected, with the worker's message. Saving a query that is already saved renames it. Delete and Clear history show the undo bar for 10 seconds.
- The command palette lists each saved search as "Search: <name>". Running it opens the pane if needed, including in focus mode, and sets the mode and Match case. Match case is one setting, so running a saved search with it on leaves it on.
- The dark theme replaces every book text and background colour, so code colouring is lost there. Sampled real books had up to 37% of text runs under 3:1 without it. The light theme keeps the book's colours.
- A book cannot hide its chapter root, but it can still hide elements inside, because hidden notes are legitimate.
- A saved place is written without fsync, so a power cut can lose the latest one.
- Rename changes the contents label. It changes the chapter's heading and `<title>` only when they read the same as the old label, or when the book has no contents to hold the name. The file name never changes, because other books' links, marks and saved places name it.
- A new chapter takes its stylesheet links from the chapter before it, and its file goes in that chapter's folder as `chapter-NNN.xhtml`.
- `dcterms:modified` is left alone, so an undo returns the package byte for byte and a plan stays pure.
- The rail's chapter actions show in Edit only, as in the reference, so a wheel or stray drag cannot reorder a novel while reading. The palette offers them in Read too.
- Deleting a chapter unwraps links to it in other chapters, so the book stays valid: the link's text stays and the link goes. An `id` on the link survives on a `span`. This relaxes unit 11's byte-equal rule for those linking chapters only. Every other chapter keeps its record byte for byte.
- Undo after a delete puts those links back byte for byte, unless that chapter was edited since, when the edit stays, the link stays plain text, and a warning says so. A chapter restored out of order, or reverted alone, stays without links to chapters that are still gone.
- A spine row the contents do not list travels with the listed row before it, unless it is the contents page.
- Deleting a parent keeps its children, lifted to its level. An unlinked parent with no children left goes too.
- Package files not stored as UTF-8, or damaged enough to need repair, refuse chapter operations rather than guess.
- A book with no contents document does not gain one. Add, move, delete and rename still work on the spine and headings.
- The shelf is a managed library, as in Calibre. A book is on the shelf only when it was added: dropped on the library page, picked with Add to shelf, made with New book, or added from the reader. Adding copies the EPUB into `library/` in the data folder (`~/.local/share/jadeslip/library/`, or `$JADESLIP_DATA_DIR/library/`), and the shelf record points at that copy. Reading and editing a shelf book change Jadeslip's copy. The file it was added from is never opened for writing, moved or deleted. Export a copy writes the book out.
- Opening is not adding. A double click in the file manager, `jadeslip book.epub`, a drop on the reader and Open EPUB read the file where it is. It does not join the shelf or the strip, and its edits go to that file, with the usual backup before the first edit. Its place is still kept, in `books/<key>/shelf.json` beside its other data, so opening the same file again resumes, and adding it later carries the place, notes and backups along.
- A book opened in place shows Add to shelf in the reader bar and in the palette. It copies the file in and reopens the book from the copy at the same place, so the next edit goes to the copy. The toast says so.
- Copies are named `<title> - <first 8 hex of the key>.epub`. Rust builds the name from the key and the title in the book. Slashes, control characters and `\ : * ? " < > |` become spaces, a leading dot goes, and the title stops at 80 characters or 160 bytes. The page sends a key or nothing, never a path or a name.
- A copy is written to `library/.adding-<pid>-<n>.tmp`, hashed while it is read, fsynced with the source's modified time, checked against the source's stamp and hash, opened to read its key, then hard-linked under its name and the folder fsynced. A name that already holds other bytes is never replaced: the next name is `<title> - <tag> (2).epub`. A name that holds the same bytes is used as it is, so a repeated add or a resumed migration finds its own copy. Stage files left by a process that is gone are removed on the next launch.
- The duplicate rule is the book's key, the same fingerprint and aliases the shelf has always used. Adding a book whose key is already shelved makes no copy and offers the existing one: "Open it" from the library, "Open the shelf copy" or "Keep reading this file" from the reader. A newer version of the same title from elsewhere has a different fingerprint and no alias, so it is a second book with its own copy. A book edited in Jadeslip keeps its key through its alias, so it is never a second book.
- Adding a book whose shelf record points at a missing copy, or at a file outside `library/`, copies the file in and repoints that record instead of making a second one. Find the file on the missing-book card works this way.
- Adding a book that was removed with its copy kept brings that copy back, with the edits made before the removal, rather than copying the added file again.
- New book writes the book straight into `library/` and shelves it, with no file window. Its name comes from its title like any copy.
- Migration runs on every launch, on a thread started with the session, and does nothing once every record points into `library/`. For each record whose file is outside `library/`, still there and still the same book, it copies the file in as above and then changes only that record's `path`. Place, notes, marks, cover, word count, own mark, backups and history stay where they were, because they are keyed by the book's key and a byte copy keeps the key. Last opened does not change. A record whose file is missing or now holds another book is left as it is and shows the missing-book card. The first time there is anything to move, `library.json` is copied to `library.json.pre-managed` first, and that file is never written again. Opening a shelf book, adding, removing and New book wait for the move to finish, so no edit can land in a file the shelf is about to stop pointing at. The page polls `library_moving` and shows "Copying your books into Jadeslip's library, N of M" while it runs, then one line saying how many books Jadeslip now keeps a copy of, until clicked. A launch with nothing to move shows nothing.
- Every step of a migration is safe to kill. The record changes only after the copy is complete, synced and named, and a copy is only ever named whole. A test kills a child process at each of the 26 durable steps of a five-book migration and checks that the originals are byte and time equal, the shelf still reads, the next launch finishes the job with one copy per book, and the backup holds the old `library.json`.
- The library page has a "Pick up where you left off" strip on top with the last three books opened, each with one button: Resume, Start reading, Read again or Continue writing. The latest also shows the passage where you stopped. Below it every book shows as a cover with a progress bar, filtered by All, Reading, Not started, Finished and Mine, searched by title or author, and sorted by last opened (the default), title, author, progress, chapters or size.
- A grid and list switch sits beside the sort. The list is a table of thumbnail, title and author, progress, chapters, size and last opened, with the selected book's place, passage, Resume and facts in a panel on the right. A column header sorts by that column. The strip stays in both views and can be hidden in the list. The view, the sort and the hidden strip are kept in `prefs.json`.
- One click on a cover opens the book at its saved place. One click on a list row selects it, and a double click or Enter opens it. Arrows move the selection, by a row with Up and Down in the grid. Enter resumes, E opens in Edit, and the Menu key or Shift+F10 opens the book menu, as does a right click or the ... button.
- Rare actions live in the book menu: Open in Edit (Read it for your own book), This is my own book, Show file in folder, Export a copy, Clean up book and Remove from shelf. Clean up book opens the book and then the clean-up dialog. In the reader, the More button at the end of the header holds Clean up book, History and snapshots and Export a copy.
- The place on the shelf is named by the chapter's own title, as in the footer, never by spine position, so chapter 1,818 no longer reads as "chapter 1,973 of 6,193". A grid card shows the chapter number from the title, as in "Ch 1,818", or only the percent when the title has no number. The passage drops a leading copy of the chapter title.
- Your own books show the chapter where you stopped and their word count instead of a percent. Colour and cover pattern of a book with no cover come from its identity, so a book keeps its look.
- New data, all in the data folder, none in the EPUB:
  - Last opened is the record's existing `touched_at`. It is stamped when a book is opened, when its place is saved, and after a save, a chapter change or a revert. Marking a book as your own or reading its cover does not change it. Nothing new is stored for it.
  - `words` in `library.json` holds an own book's word count and the file stamp it was counted at. It is counted on a background thread after a save that wrote, after a chapter change, a revert or a history restore, when an own book opens with a stale or missing count, and when a book is marked as your own. The save returns before the count starts, and a count whose file has since changed is dropped, so the last save's count wins. Words are runs between spaces, the same rule as the editor's word count. The 6,191 chapter test book counts in about 475 ms.
  - `books/<key>/shelf.json` keeps the record of a book that is not on the shelf: one removed from it, or one opened in place. Adding the book brings back its place, its own-book mark and its count, and the file goes.
- Show file in folder runs `xdg-open` on the folder of the shelf record's path, which is `library/` for every shelf book. The page sends only the book's key, and the folder comes from `library.json`, so the page cannot name a path. No Tauri plugin or capability is needed: the app's own commands are not gated by capabilities, and `capabilities/main.json` stays empty.
- Export a copy from the shelf opens the book file without adding it to the shelf or touching its last opened time, refuses a file that now holds a different book, and writes the same verified copy as Export a copy in a book.
- Remove from shelf asks first. By default it removes only the shelf record, and the file, backups, history, notes, drafts and place stay. Two boxes, both off, add "Also delete Jadeslip's data for this book", with its size, and "Also delete Jadeslip's copy of the EPUB", with its size. The file the book was added from is never touched, and the copy box shows only when the record's file is inside `library/`. Nothing is deleted outright: Jadeslip moves its copy of the EPUB, the book's `books/<key>/` folder and every `aliases/` file that points at this book into the freedesktop trash at `$XDG_DATA_HOME/Trash` (or `~/.local/share/Trash`), with a `.trashinfo` file, so the file manager can restore them. If any move fails, the ones already made are moved back and nothing is removed. A book on another drive than the home folder cannot use the home trash, so that move fails and says so. Another book's aliases and data are never touched, because every per-book file lives under that book's own key. The trash date is written in UTC.
- The command that removes is `remove_book(key, data, file)`. The file it trashes is the shelf record's path, and core refuses to trash a path outside `library/`, so a record left pointing at an original by the migration can never take that file with it.
- The shelf shows a book's own cover when it has one. A book without one keeps its generated look. The cover is the EPUB 3 `cover-image` item, then the EPUB 2 `cover` meta, then an image whose id or file name contains "cover". A candidate that is not JPEG or PNG, or is missing from the ZIP, falls through to the next rule. SVG, GIF and WebP covers count as none, and a cover page is not searched for an image.
- The cover is read when the book opens, on a background thread started once the first chapter is rendered, and kept as a JPEG of at most 400 by 600 px in `books/<key>/cover.jpg` in the data folder. The shelf record stamps the file's length and modified time. A stamped book is not read again until its file changes and it is opened.
- A book shelved before covers existed, or added by drop, Add to shelf or New book, has no stamp. A copy keeps its source's modified time, so a migrated book keeps its cover and word count stamps. The shelf reads such books once, one at a time, after it shows. Every other launch opens no EPUB. Covers in the strip load at once and grid and list covers load lazily.
- The page never gets the book's own image bytes. Core decodes JPEG and PNG only, refuses an entry over 16 MiB, a side over 6,000 px or a decode over 128 MiB, and serves only the JPEG it wrote, at `jadeslip-book://cover/<key>`.
- A shelf book whose copy is gone stays on the shelf. Opening it shows where it was, with Remove from shelf and Find the file. Removing there keeps its backups and its marks.
- Dropping files on the library adds every one and opens none. One duplicate gets the offer, several are listed in a toast, and a file that is not a book is named in the failure bar. Dropping files on the reader opens the first in place.
- Closing the window in Read now waits for the page to save the place, up to 400 ms, instead of closing at once. Unit 7's fall-through for a page that does not answer stays.
- Export a copy lives in the palette and the shelf's book menu. The Aa panel's Book tab held only that button and is gone.
- A mark whose words were corrected is still found, through the text on both sides of it. A word under 16 characters with under 4 matching characters of context is detached rather than guessed.
- The contents page cannot be reverted on its own, because it changes with the book. The whole-book revert covers it.
- While a native file window is open the page shows a wait message and takes no keys, because the system window does not block the page.
- Editing an exported copy moves the backup's record to the copy, so the original then reports a different copy and offers no revert until its next edit starts a new record. No bytes are lost. This follows from a copy having the same identity.
- A note cannot be edited in version one, as in the reference. Delete it and add it again.
- A damaged `library.json` is set aside beside the new one, and a damaged `marks.json` is refused and left in place, so nothing the user wrote is overwritten.
- Undo right after a delete restores the package files byte for byte. After other structural changes it restores the chapter and flat contents rows near its place, without the original nesting.
- Spelling marks show in Read and Edit. Suggestions and add to dictionary are in Edit only, from a right click on a mark.
- An unknown capital word inside a sentence counts as a name, along with every copy of it in that text, because names were about 95% of marks on the long real novels. A typo that happens to be capitalised mid-sentence goes unmarked. At a sentence start with no such copy, it is marked.
- The bundled dictionary is en_US only, so British spellings are marked until added or until an English Hunspell dictionary such as `en_GB` is installed. `ok` and `Ok` are also marked, because SCOWL size 60 lacks them.
- Other languages come from Hunspell pairs in `dictionaries/` in the data folder, named `<code>.aff` and `<code>.dic`. Nothing beyond English ships in the repo. A pair is read only when a shown chapter needs it, after first text, and a `SET` line's character set is honoured.
- Auto picks the installed dictionary whose name matches the book's `dc:language` exactly, then by primary subtag, and otherwise behaves as English did before. `tl`, `fil` and `tgl` count as one language, so a Filipino-tagged book uses a `tl` dictionary. That alias table is the only language-specific code.
- Auto reads the book tag from `dc:language` only. An `xml:lang` on a chapter's root is not consulted, while `xml:lang` on a passage inside the text still exempts that passage from a dictionary of another language.
- An installed dictionary named after an English tag, such as `en_GB`, replaces the bundled one for books tagged that way.
- The per-book choice (Auto, English, or an installed dictionary) lives in `books/<key>/spelling.json`. A choice whose dictionary was removed acts as Auto.
- A dictionary that fails to load shows one toast per session, and the book falls back to the English behaviour, or to no marks when the book is not English.
- The on and off switch is global, in the settings file, not per book. Off stops every check, so no dictionary loads at all.
- A book whose `dc:language` is not English and has no installed dictionary gets no marks, so a mislabelled English book gets none either, unless English is chosen for it in the Aa panel. Passages tagged with a language other than the one checking the book, and text in `code`, `pre`, `kbd`, `samp`, `var` or `tt`, get none. Untagged foreign Latin text in an English book is marked.
- All-capital words, words with digits, non-Latin words, addresses and runs over 40 bytes are not checked. One chapter shows at most 5,000 marks.
- Added words live in one list per dictionary, one word per line, for every book in that language: `spelling-words.txt` for the bundled English and `spelling-words.<code>.txt` for an installed one. A name added in one language is not added to the others. Version one has no UI to remove one, so the file is edited by hand.
- Unsaved edits found after a crash block Edit on that book until they are recovered or discarded, so new edits never overwrite them. Recovered edits are not in Undo.
- Rewritten entries are compressed with zlib-rs at level 6 instead of miniz. On an all-chapters replace of the 6,000-chapter generated book it took 76% of miniz's time and 74% of its CPU, and the file came out 52 KB smaller. Every entry inflates back to the same bytes.
- Every save keeps the previous bytes of each file it changed in `books/<key>/history/log` in the data folder, never in the EPUB. Until a cleanup, the log grows by the compressed size of each changed chapter's old version per save. A one-chapter save adds about one chapter, and a book-wide replace adds about the whole book's compressed text once.
- A history version is keyed by the SHA-256 of its stored compressed body, which is copied from the ZIP as is. A save costs no recompression, and the old version that the next save keeps is the same body, so it is stored once. The same text compressed two different ways is stored twice.
- The history record and its versions are written before the book is renamed into place, so a crash cannot lose an old version. A save that then fails leaves a record that names a file which never landed, and the list leaves it out.
- A save whose history write fails still saves and shows a warning. The history then has a gap, so points before it restore single chapters only, never the whole book.
- History points mean the book as it was just before that save, so restoring the first save's point undoes that save. A named snapshot means the book as it was when it was taken.
- A restore is itself a save in the history, so it can be restored away again.
- A save that changed no file is not listed.
- History is one append-only log of checksummed frames, not one file per version. A file per version needs its own sync and rename, measured at 5 to 10 ms each against a 56 ms one-chapter save. The log needs one sync. It starts after the new book file's own sync, runs while the file is verified and the backup record's pending write lands, and must finish before the rename. On btrfs two syncs at the same moment queue behind each other, so it does not start sooner. A torn last frame is ignored and cut off by the next write.
- The diff compares the visible text paragraph by paragraph, then word by word inside changed paragraphs. Unchanged runs longer than five lines show their first and last two lines.

- Clean up book removes web-novel junk in one save. It has four rules: watermark lines, translator notes and support requests, repeated chapter titles, and fix chapter titles, which writes each title as its number and name in the heading, the `<title>` and the contents. Empty paragraphs are not a rule, because spacing between scenes is often made of them.
- The rules are data: `RULES` in `crates/core/src/clean.rs` holds each rule's label, its one-line description and its patterns with a length cap. The dialog reads labels and descriptions from it through `cleanup_rules`, so changing a rule or adding a pattern touches one table. `jadeslip clean-report <book> [--samples <count>] [--all] [--titles]` prints what each rule finds in a book, which is how the patterns were tuned on the real books.
- A removal rule removes a whole paragraph or nothing. A paragraph is a block element, or one line of a `<div>` split by `<br/>` runs, so a line and its trailing `<br/>` run go together and the blank line between the lines that stay is kept. Text inside a story paragraph is never cut.
- Deliberately not matched: a line that opens with a quote mark (so dialogue that mentions Patreon stays), a line longer than its pattern's cap (400 characters for a support request), so a story paragraph that mentions a sponsor stays, a web address with a path unless its site name holds "novel", and a first paragraph that repeats the title in a chapter with no heading element, since there that paragraph is the only title.
- Counting is one preview run in its own slot, so it never cancels a pane search or a fix offer. The dialog shows each rule's paragraphs and chapters, and Show matches opens the search pane on the same rows, with the struck paragraph, its rule and the tick and Skip chapter buttons. Neither Show matches nor Clean up runs the rules again. A preview keeps up to 20,000 rows, against 5,000 for text replace. On the largest real book (6,127 chapters) the rules find 4,342 paragraphs.
- The clean-up goes through the replace pipeline, so it inherits the backup before the first edit, the managed copy for shelf books, the stale-preview check and one history point. Undo in the bar after the save restores that point for the whole book. It refuses, pointing at History, when a newer save exists, so it never undoes edits made after the clean-up.

- Page mode is Scroll or Auto in Preferences > General and in the palette. Scroll stays the default. It is saved in prefs.json. Reset layout leaves it alone, as it leaves text size and theme.
- There is no fixed 1 page or 2 pages. A forced 2 pages at 1256 px beside the contents squeezed each page to 22 em, and one column read better there. A prefs.json that says "one" or "two" opens as Auto, and the next save writes "auto".
- A page is at most the column width. The gap between two pages is the right margin plus the left margin, and the top and bottom margins frame the page.
- Auto picks one or two pages from the room and the text size alone: two when each page can hold 36 em of text, about 70 characters, else one. It ignores the column width slider for the choice, the way Calibre's zoom scales its columns, so Ctrl and the wheel flip it. At 18 px a 1256 px window beside the contents shows one page, and a 1920 px screen in focus shows two up to 24 px and one from 25 px. Window size, the contents, the search pane, full screen and text size all recompute it, and the place is kept across the flip. In Edit it scrolls.
- In page mode Right, Down, Page Down and Space turn forward, and Left, Up, Page Up and Shift+Space turn back. Right and Left turn pages, not chapters, there. Past a chapter's last page comes the next chapter's first page, and before a first page comes the previous chapter's last page. The footer's Previous and Next stay chapter buttons.
- A click turns a page only outside the text column, left of it back and right of it forward. A click on the text selects as before, and a double click still opens Edit.
- One wheel notch turns one page. Wheel turns are at least 200 ms apart, so a trackpad flick turns about one page per 200 ms.
- Edit always scrolls. E from page mode puts the caret on the first text of the page. Esc goes back to the page holding the caret.
- The page count is per chapter and counts columns, so two pages read "Pages 3-4 of 12".
- Images taller than a page shrink to fit it.
- Pages are CSS columns on the chapter host, moved with a transform. A test build moving them with scrollLeft did not split the chapter into columns in WebKitGTK, and container size units broke the page height, so the page height reaches images through a property set from script.

- Chrome sizes come from tokens on `.app` in `app.css`: a 4px spacing scale, type at 12, 13, 14, 16, 20 and 28px in IBM Plex Sans, controls 32px tall (28 compact, 40 for dialog and hero primaries) and radii 6, 10 and 12. `tests/ui/tokens.test.mjs` fails on a font size or control height outside them. The spine count keeps 10px because it is cover art and wider text overflows thin spines.
- A standalone toggle shows its on-state as accent text, the tint fill and a 1px `--on-edge` ring, 3:1 or better against the panel in both themes. A segmented control is one filled `--raise` track with no border, and its chosen segment is a solid `--accent` fill with the `--on` label, so it does not read as a box inside a box. The label is 9.9:1 on the fill in dark and 6.5:1 in light, and the fill is 8.7:1 and 5.4:1 against the track. Control edges use `--edge`, 3:1 or better. Disabled is 45% opacity with no hover.
- Icons are Lucide 0.460.0 (ISC, `app/ui/LICENSE-Lucide.txt`) as an inline `<symbol>` sprite at the top of `index.html`, used with `<use href="#i-name">`. Nothing is fetched, so the page policy is unchanged. `python3 -I scripts/lucide-sprite.py <unpacked lucide-static>` rebuilds the sprite from every `#i-` name the UI uses.
- `BINDINGS` in `keys.js` lists every shortcut once, the library's arrows, Enter, E and Menu included. Button tooltips and the F1 sheet (also `?` in Read, and a palette command) read it, and `tests/ui/keys.test.mjs` checks each listed key against `actionForKey`. New keys: Ctrl D notes, Ctrl , Preferences (in Read, Edit and on the shelf), Ctrl Shift A the Aa panel, Ctrl L library.
- Below 1100px wide the Contents, Search and Notes panels slide over the text instead of narrowing it. There Contents is a passing overlay, not the saved setting: picking a chapter, Esc or a click on the text closes it, so a narrow launch never opens with the text covered.
- Edit's toolbar ends with the chapter's word count and Save. Save is a quiet "Saved" check while clean and the accent Save once there are changes. The count runs on entering Edit and 400 ms after typing stops, never in the input path. Fix everywhere lives in the offer bar and the palette, not the toolbar.

## Preferences and storage cleanup

- Preferences is a dialog with General, Reading, Spelling, Storage and Shortcuts. The gear in the reader's top bar and on the shelf, the palette's Preferences and Ctrl , open it. Ctrl , opened the Aa panel before, so Aa moved to Ctrl Shift A, which nothing used in Read, Edit or a field. Plain Ctrl A stays select all.
- Every setting is app-wide, as before. There is no per-book look. Preferences > Reading changes the same spacing preset, text size and font as Aa, so Aa is the quick control while reading and Preferences the complete place.
- Aa keeps text size, font, spacing, the layout sliders, Full screen and Reset layout, and a Spelling tab that holds only the book's language. Theme and page view moved to General, spelling marks on and off to Spelling. The palette commands for all three stay.
- Theme has Dark and Light only. A System choice needs the theme before the window exists, for its background and the UI scheme, so it is left for later. Opening the last book on launch does not exist and is not added here.
- Spelling lists the bundled English and each installed Hunspell pair with its count of added words, and opens the dictionaries folder. A book's language is still chosen in Aa.
- Storage shows the data folder with Show in folder, its total size, and a row per shelf book with its file in `library/`, its history, original backup and other data. A `books/<key>` folder whose book left the shelf shows as Not on the shelf.
- "Keep automatic snapshots for" offers 7 days, 30 days, 90 days, 1 year and Forever, saved as `keepSnapshots`. Named snapshots, the newest point and the original backup are always kept. A prefs.json from before this setting, or one that cannot be read, keeps Forever, because history was kept forever until now and a first cleanup must not delete what the user expects to find. A new install with no prefs.json starts at 90 days, because it has nothing old.
- Choosing a shorter period first counts what it would remove. If anything, a confirm names the points, the books and the size, and Cancel keeps the old period. Keep saves it and cleans up at once. Clean up now runs the saved period and shows the space freed.
- Cleanup also runs on a background thread at launch, at most once a day, stamped in `cleanup.json` in the data folder. It skips the open book and any book another window is saving. Clean up now includes the open book, whether or not it is on the shelf.
- A cleanup rewrites a book's history log. Points older than the cutoff are dropped, except named snapshots and the newest point. A dropped run's versions fold into the kept point before it as carried versions, first version per file, and its end hash moves forward, so the kept point restores exactly as before and its History row still lists only the chapters its own save changed. Folding never crosses a gap left by a failed history write, so points before a gap still restore single chapters only. Points before the first kept one are simply dropped. Only versions a kept point needs are copied, as stored, with no recompression.
- A restore's target is renumbered. A restore whose target was dropped reads "Restored".
- The new log is written to `log.new` beside the old one, synced, read back and compared with the old one. Every kept point must give the same versions, row count and completeness, every version it needs must read back, and the newest point must survive. Only then is it renamed over `log`. A crash before the rename leaves the old log and a temp the next cleanup removes. A log that fails the comparison is left as it was. A History reader notices a replaced log by its device, inode and creation time and reads it again.
- Point ids are positions in the log, so a cleanup renumbers them. The History dialog reloads its list when it opens. An older Jadeslip build ignores carried versions and would show wrong versions for folded points in a cleaned log.

## Rules for every unit

- No comments in code at all, including `///` doc comments and tests. No exceptions. No AI attribution in commits.
- Book content is never quoted in logs, tests, commits or reports. Use generated fixtures in committed tests. Real-book checks live in an ignored test run and print counts only.
- `fixtures/real` is read-only. Copy before any write.
- GUI test runs go on a headless Hyprland output, class `jadeslip-test`, never on the user's screen. `tests/e2e/headless.sh` creates the output, adds the rule, runs the command and always removes both. Every GUI run uses it.
- A verdict is VERIFIED, NOT VERIFIED or INCONCLUSIVE, based on the artifact rather than a self-report.
- A test folder outside `target` comes from `jadeslip_fixtures::scratch`, never straight from `temp_dir()`. `/tmp` is RAM, and that root is removed when the test process exits or, after a kill, by the next test run. E2E files go under `target/e2e-run/<suite>`, which keeps only the last run of each suite.
